# Roadmap
Каждый этап — отдельная ветка/PR и проверяемый результат. Не начинать следующий, если блокирующие критерии не выполнены.
- v0.0.1 spike: клиентский тест API, минимальный TOC, ручной Screenshot, подтверждение результата, протокол совместимости. Gate: воспроизводимый снимок в Forever.
- v0.1.0 MVP: Init/DB/API/Events, уровень и подтверждённые зоны, ручной режим, базовые настройки, очередь, cooldown, безопасная обработка загрузки, лог, RU/EN. Gate: тесты MVP и реальная игровая сессия.
- (выполнено в 0.4.x, частично отменено в 0.5.0) v0.2.0 Smart Capture: дополнительные подтверждённые триггеры, приоритеты, объединение, лимиты, серия/dual/clean при успешном spike, пресеты. Gate: отсутствие зависания UI при отменах, бою, ошибке.
- v0.3.0 Journal: история, фильтры, профили, миникарта, путешествие, статистика, заметки, избранное. Gate: миграции, лимиты хранения, сохранение после reload.
- v0.4.0 Polish: ручная панель, подпись если возможна, Time Capsule, Anniversary, масштаб, доступность, локализация.
- v0.5.0 UX Update & Step Tracker (ТЗ 2026-11-24, приоритет над пунктами выше): 4 вкладки, 9 событий, 2 режима, без профилей/пресетов/путешествия, история по персонажам, шагомер с графиком 7 дней, миграция 0.4.2 → схема 3. Gate: чек-лист клиента в TESTING.md.
- v0.5.x: исправления по итогам игры; оптимизация интервала шагомера по замерам; решение о ключе персонажа по GUID после проверки его стабильности.
- v1.0.0: регрессия на актуальной сборке Forever, README установки, CHANGELOG, LICENSE (MIT при согласии автора), релиз ZIP с корректной корневой папкой. GitHub; площадки аддонов только если поддерживают Forever.
- Backlog: внешняя галерея/переименование файлов — самостоятельный проект, не часть аддона.
## Правила разработки с ИИ
Сначала прочитать весь комплект. Не генерировать все модули одним шагом. Перед каждым этапом перечислить файлы и критерии приёмки; после — показать изменения, тесты и непроверенные допущения. Не выдумывать API. Использовать Conventional Commits, SemVer, CHANGELOG. Вести PROGRESS.md и API_COMPATIBILITY.md. Не заявлять прохождение клиентских тестов без реального запуска. Не изменять согласованные требования молча.
