## Найденные противоречия и решения

1. **Interface не указан в ТЗ.** Взят `16001` по Warcraft Wiki. Подтвердить по 4-му значению `GetBuildInfo()` (`/fm status`).
2. **Forever работает на Mainline API (12.1.5), а не на Classic.** По данным сообществ combat log аддонам недоступен, GUID обфусцированы, часть значений — secret values. Риск для триггеров RARE (нужно знать, что убит редкий противник), BOSS вне `ENCOUNTER_END`, DUEL, BG. Решение: не гадать, проверить отдельные события в v0.1.0/v0.2.0; неподдерживаемые показывать как недоступные (как и требует ТЗ).
3. **`SCREENSHOT_*` не содержат payload.** Нативный Print Screen неотличим от нашего снимка. Решение (уже в ТЗ): один активный запрос, таймаут 5 с, карантин 5 с, чужие сигналы только считаются.
4. **Приоритет MANUAL = 0**, а редактор в UI_DESIGN допускает 1–4. Предложение: 0 — служебное значение только для ручного кадра, в редакторе не показывается. Требует согласия автора.
5. **`tests/` и `docs/` внутри папки аддона** (ARCHITECTURE §2) vs «релиз ZIP с корректной корневой папкой» (v1.0.0). Решение: при сборке релиза исключать `tests/`, `docs/`, `*.md` кроме README/LICENSE.
6. **Схема данных ARCHITECTURE §5** пока не реализована: spike хранит данные в `ForeverMemoriesDB.spike`. В v0.1.0 — миграция, `spike` удаляется.
7. **`/fm` без аргументов должен открывать окно**, а окна в v0.0.1 нет. Временно показывает справку.
8. **ROADMAP требует ветку/PR на каждый этап**, но GitHub-репозитория у проекта нет. Сейчас файлы лежат в папке проекта. Первый коммит, когда появится репозиторий: `feat: add v0.0.1 spike with manual screenshot and API probe`, тег `v0.0.1`.

## Непроверенные допущения
- `Screenshot()` не защищён и работает из slash-команды (если защищён — сработает `ADDON_ACTION_BLOCKED/FORBIDDEN`, аддон это покажет в чате).
- `SCREENSHOT_SUCCEEDED` действительно приходит после нашего вызова (синхронно или асинхронно — измерим).
- 5 с хватает для результата на диске пользователя.
- Первое значение `ADDON_ACTION_*` — имя аддона.
- Системная надпись клиента после снимка не мешает следующему кадру (важно для серий и clean в v0.2.0).
